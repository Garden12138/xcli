# R3 启动检查 · 2026-10-17

结论：**可以开始 R3 开发与验证准备；当前不代表满足正式发布条件。** 下一阶段采用 [产品调整路线](product-realignment.zh-CN.md)中的 R3“验证价值与收敛发布”，不沿用旧阶段编号推导新的功能范围。

## 已具备的前置条件

| 前置条件 | 检查结果与证据 |
| --- | --- |
| 一个 Task 入口与两种执行模式 | R1 已交付，Work/Project × 指定/自动四路径有真实记录 |
| 后台、检查点、stop/continue 与恢复 | R2 已实现；真实后台、同 session 恢复、控制进程中断及材料恢复通过；两种模式有模拟重启回归 |

具体结果与不同验收二进制的范围见 [R2 记录](../r2/results.zh-CN.md)。原 R2 真实执行预算已用完 24/24 次，本次启动检查没有追加模型调用；R3 的真实实验需单独确定场景和累计调用上限。

## R3 建议顺序与交付

1. **先做可重复的对照实验入口。** 冻结材料、项目基线和预置缺陷，比较直接使用单 CLI、Task 指定单 CLI、Task 跨 CLI；输入、预算和完成标准可比较。记录完成率、可复现遗漏/发现、误报、人工交接次数、耗时和可观察用量。保留失败样本，避免以参与 CLI 数量或单次偶然成功证明收益。
2. **安排少量独立用户观察。** 提供从安装、首次任务、失败诊断到隔天继续的脚本和记录表；建议首批三位已有 CLI 用户独立操作，记录求助与阻力，再决定是否扩大样本。此工作需要真实参与者，自动化夹具不能替代。
3. **补齐拟声明支持范围的兼容与安装证据。** 固定 CLI 版本和 OS/架构，覆盖 run/JSON/resume/取消与 Task 恢复，在干净环境检查归档安装。保留未测清单，不能把跨平台编译当原生 CLI 实测。
4. **收敛候选与发布材料。** 根据实验和观察修复直接阻碍任务完成的问题，更新中英文教程、迁移说明、演示和 release notes；在固定候选上完成回归、归档及 GoReleaser 门禁，再作发布判断。

R3 首轮应优先补实验、记录和分发验证，不先增加新的团队模式、并行写入、常驻调度、账号管理或自动 Git 合并。至少一个预定义场景需展示可复核的协作收益；若没有收益，应记录结论并收缩对外主张。

## 尚未具备的发布证据

- 尚无直接单 CLI 与协作模式的受控对照，也没有独立用户的本阶段观察记录。
- 本机没有运行 GoReleaser snapshot，工具未安装；仓库 CI 已固定对应版本，推送后的 test/build/package 结果需按实际提交核对。
- 未实测的 Adapter/平台、真实机器重启及持续满 30 分钟运行仍未验证。现有模拟重启和 30 分钟预算任务不能替代这些证据；若拟对外承诺，应在 R3 补齐，否则收窄声明。
- 尚未形成 R3 的最终版本兼容矩阵、干净环境安装结果、演示与发布评审结论。

这些是 R3 要完成的工作，不构成启动实验和验证工具开发的阻断。当前无须为启动 R3 补做超出既定范围的 R2 模型调用，也不应现在创建发布 tag。
