## 本轮真实补验入口与标准

新增 `tests/r3/revalidate.py`，在显式确定的本轮预算下准备独立账本，并按摘要关联旧账本。输入、工具、二进制与原生版本先冻结，失败记录不得借更换输出文件重跑。

1. Cursor 进行一次只读真实请求。未通过时保留失败，跳过跨 CLI 场景，不自动重试或替换工具。
2. 指定 Codex：观察运行中的 worker 创建进度标记并保持 running，执行 stop，确认 paused 与该 worker 的 canceled 状态；随后在同 Task 上从材料新建原生 session 完成并自查。
3. Codex 执行 / Cursor 复核：同样中断实际 worker 并从材料继续，最终由 Cursor 对当前内容摘要完成复核。

两个恢复场景都必须保持 Task 身份、执行模式、候选池、登录配置绑定与累计预算，保留中断 attempt，验证新 worker 的 session 与旧 session 不同，当前产物和复核一致，完成后重复 continue 不增加调用。等待用户的闲置 Task stop 或澄清后继续，均不能替代实际 worker 中断。

每个恢复场景最多五次分派，可以单独记录一次协调计划澄清；发生澄清时标明操作员介入。新增上限已确定为 12 次，正常路径预计九次（可用性一次、两个恢复场景各四次），不为耗尽预算追加调用。
