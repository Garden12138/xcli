## 建议优先级

1. **补充 Project 接收说明。** 给出审查完整 diff 和未跟踪文件、检查补丁可应用性、人工接收后重测的步骤；说明先在 worktree 提交再走 Git 流程也是选择。当前没有阻止熟练角色完成检查，优先级低。
2. **给参数错误附合法示例。** `--verify` 可提示 `'["go","test","./..."]'`，路径错误可提示检查 `--input`。当前均有明确错误和非零退出码，属于易用性改进。
3. **澄清取消事件。** 考虑在 worker `failed` 事件携带取消原因，便于脚本区分用户停止和工具失败。混淆风险属于假设，本轮没有发现违反公开契约。

本轮按“试用后反馈”的范围交付建议，未修改生产 Task 行为。
