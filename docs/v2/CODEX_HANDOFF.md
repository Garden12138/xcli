## 这个项目要做什么

xcli 是一个本机多 CLI 编排引擎：通过启动真实的 `codex exec`、`cursor-agent -p`、`agy --print` 进程，把编码、文本、审查、生图能力以子进程 JSON 协议提供给桌面应用，并能按需求自动编排多个 CLI（规划 → 并行/串行 → 实现-验证-审查-修复 → 失败切换）。目标是**简单好用**：装好并登录 CLI 后零配置可用。

## 执行规则

1. 严格按 `04-implementation-plan.md` 的任务顺序执行。每个任务：先写测试 → 实现 → `go build ./... && go vet ./... && go test ./... -race` 全部通过 → 单独提交（conventional commits）。
2. 计划里给出的类型名、函数签名、参数顺序、文件路径是跨任务的约定，不要改名。确实需要改时，同时修改计划文档里所有引用的地方，并在提交说明里写明原因。
3. 设计文档与计划冲突时以设计文档为准；发现设计本身有问题时，先停下来说明问题和建议，不要自己另起炉灶。
4. 每完成一个任务，用三五行汇报：做了什么、测试结果、当前非测试 Go 代码行数、与计划的偏差。

## 必须先停下来问用户的情况

- 任何会真实调用 codex / cursor-agent / agy 的操作（任务 2、任务 16 步骤 6、任务 17 步骤 3、`scripts/smoke.sh`），因为会消耗用户的额度。`--version`、`--help`、`login status`、`status` 这类不调用模型的命令可以直接运行。
- 需要新增计划之外的第三方依赖。
- 非测试 Go 代码超过 8000 行。
- 想增加计划之外的命令、配置项或协议字段。

## 明确禁止（旧版就是因为这些变得难用的）

- 不要加入启动窗口、启动账本、预算预留、授权回执、外部启动计数、`reconcile` 之类的门禁或确认流程。
- 不要实现 OpenAI 兼容接口、chat/completions、模型反代、OAuth、凭据管理。
- 不要在用户执行任务前要求额外的初始化或授权步骤；所有配置项都必须有默认值。
- 不要写验收报告、证据清单、source manifest、阶段进度文档。`docs/v2/` 下只允许存在计划里列出的文件。
- 文档和错误信息不要写成否定式免责声明（"不代表……"、"不能推导……"）；错误信息要告诉用户下一步该做什么。
- 不要从 `archive/r4.1-final` 整块复制旧代码；只参考计划里点名的几个文件中的解析经验，然后按新接口重写。
- 单元测试不得启动真实 CLI：测试一律通过配置 `path` 指向 fakecli。

## 遇到真实 CLI 行为与设计不符时

以实测为准：更新 `docs/v2/driver-notes.md`，同步修改 `02-architecture.md` 第 4.2 / 4.3 节和对应测试的期望值，在提交说明里写明"根据实测调整"。
